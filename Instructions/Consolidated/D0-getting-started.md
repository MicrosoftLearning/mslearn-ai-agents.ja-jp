# 概要

このページでは「**エージェントを観察し、評価し、安全に保つ**」ラボに必要なすべての情報を設定します。
**すべてのタスクがここから始まる** — まずはこのページを完了してください。 各タスクは、単独でできるように書かれています。一度にラボ全体を進める場合、このセットアップは一度だけで済みます。

**あなたのシナリオ:** あなたは製薬会社 **Caldova** で働いており、製品の発売に向けて急いで準備をしています。 サプライ チェーン アシスタントは稼働中で、このラボではそれが実際に何をしているのか、つまりどのようにトレースし、応答をスコアリングし、攻撃するかを確認する手段について説明します。

> **注**: このラボで使用されるテクノロジの一部は、プレビューまたは開発中の段階です。 予期しない動作、警告、またはエラーが発生する場合があります。

## 前提条件

開始する前に、次のものがそろっていることを確認してください。

- Azure AI リソースをプロビジョニングするための十分なアクセス許可とクォータを持つ [Azure サブスクリプション](https://azure.microsoft.com/free/)
- ローカル コンピューターにインストールされている [Visual Studio Code](https://code.visualstudio.com/)
- [Python 3.13](https://www.python.org/downloads/) がインストールされていること
- ローカル コンピューターに [Git](https://git-scm.com/downloads) がインストールされている
- Python に関する基本的な知識

> \* Python 3.14 はまだサポートされていません。一部の依存関係には 3.14 ビルドが含まれていません。

## Microsoft Foundry プロジェクトを作成する

すべてのタスクで Foundry プロジェクトとデプロイ済みのモデルが必要です。 これらはポータル (既定) で作成するか、Azure Developer CLI (`azd`) で 1 つのコマンドでプロビジョニングできます。

### オプション A — ポータルでプロジェクトを作成する (既定)

1. Web ブラウザーで、[Foundry ポータル](https://ai.azure.com) (`https://ai.azure.com`) を開き、Azure 資格情報を使用してサインインします。 ヒントやクイック スタートのペインをすべて閉じ、必要な場合は、左上にある **Foundry** のロゴを使ってホーム ページに移動します。

    > **重要**: このラボでは、**新しい** Foundry エクスペリエンスを使用しています。

1. 上部バナーで **[ビルドを開始する]** を選択します。

1. プロンプトが表示されたら、**新規**プロジェクトを作成し、有効な名前 (`observability-lab-project`など) を入力します。

1. **[詳細オプション]** を展開して、次のように指定します。
    - **Microsoft Foundry リソース**:"Foundry リソースの有効な名前"**
    - **リージョン**: 近くから利用可能なものを選択します**\*
    - **[サブスクリプション]**:"*ご自身の Azure サブスクリプション*"
    - **[リソース グループ]**: *リソース グループを選択または作成します*

    > \***タスク 3** (レッド チーミング) を行う予定がある場合、AI レッド チーミング エージェントを利用できるのは**米国東部 2**、**フランス中部**、**スウェーデン中部**、**スイス西部**、**米国中北部**のみです。 今はその中から選択することで、後から 2 つ目のプロジェクトを作る手間が省けます。

1. **[作成]** を選択して、プロジェクトが作成されるまで待ちます。

1. プロジェクトの**概要**ページで、**プロジェクト エンドポイント**と作成されたモデル デプロイの名前をメモしてください。両方とも `.env` に記載します。

### オプション B — azd を使用してプロビジョニングする (オプション、コマンド 1 つ)

ポータルをクリックして移動したくない方のため、ラボには Foundry リソース、プロジェクト、モデル デプロイが作成されるオプションの `azd` テンプレートが付属しています。

1. [Azure Developer CLI](https://learn.microsoft.com/azure/developer/azure-developer-cli/install-azd) をインストールします。

1. `Labfiles/D-observe-evaluate-and-secure-agents` フォルダーから、次を実行します。

    ```
    azd auth login
    azd up
    ```

1. プロンプト (環境名、Azure リージョン) に答えてください。 完了すると、`azd` によって `PROJECT_ENDPOINT` と `MODEL_DEPLOYMENT_NAME` が`Python/.env` に書き込まれます。

    > **注**: タスク 1 に必要な Application Insights リソースは、`azd up` では作成**されません** — 以下のステップを使用してポータル内で接続してください。 ラボが完了したら、`azd down` を実行して作成されたものをすべて削除してください。

## Application Insights に接続する (タスク 1 で必要)

Foundry は、プロジェクトに接続された **Application Insights** リソースにトレースを保存します。 これに接続します — 1 分かかり、接続されると Foundry はコードなしでエージェントのサーバー側のトレースを記録し始めます。

1. [Foundry ポータル](https://ai.azure.com)で、プロジェクトを開きます。

1. 左のナビゲーションで **[エージェント]** を選択し、上部の **[トレース]** を選択します。

1. **[接続]** を選択してから、既存の Application Insights リソースを選択するか、**[新規作成]** を選択してウィザードを完了します。

    > **[接続]** ボタンが見当たらない場合は、右上の **[管理]** を選択し、**[プロジェクトの詳細]** > **[接続されたリソース]** > **[接続の追加]** > **[Application Insights]** の順に選択します。

1. トレースを*読み取る*には、その Application Insights リソースに対して **[Log Analytics 閲覧者]** のロールが必要です。 自分で作成している場合は、既にお持ちのはずです。

> **これが重要な理由**: Foundry プロジェクトは接続が確立されていないとコードに接続文字列を渡すことができません。 タスク 1 ではその文字列がプロジェクトに要求されるので、このステップを先に行う必要があります。

## スタート コードを取得する

1. VS Code で、コマンド パレット (**Ctrl + Shift + P** キー) を開き、「**Git Clone**」を実行して、次のように入力します。

    ```
    https://github.com/MicrosoftLearning/mslearn-ai-agents.git
    ```

1. クローン リポジトリを開いてから、**[ファイル] > [フォルダーを開く]** を選択し、`mslearn-ai-agents/Labfiles/D-observe-evaluate-and-secure-agents/Python` を選択します。 この 1 つのフォルダーに、このラボの**すべての**タスクのスタート コードが入っています。1 つの仮想環境と 1 つの `.env` を通して使用します。

1. **[requirements.txt]** ファイルを右クリックし、**[統合ターミナルで開く]** を選択します。 その後、仮想環境を作成し、パッケージをインストールします。

    ```
    python -m venv labenv
    .\labenv\Scripts\Activate.ps1
    pip install -r requirements.txt
    ```

    > このインストールは他のラボよりもサイズが大きく、評価 SDK とタスク 3 用の PyRIT が含まれています。 数分待ちます。

1. **.env** ファイルを開いて、`PROJECT_ENDPOINT` をプロジェクト エンドポイントに、`MODEL_DEPLOYMENT_NAME` をモデル デプロイ名に設定します。 ファイルを保存します。 (`azd up` を使用した場合、これらは既に入力されています。)

    > **ヒント:** Foundry ツールキット VS Code 拡張機能で、プロジェクトのデプロイを右クリックし、**[プロジェクト エンドポイントのコピー]** を選択してエンドポイント URL を取得してください。

## 測定するエージェントを入手する (タスク 2 と 3 で必要)

タスク 2 と 3 では、モデル自身のメモリではなく Caldova のナレッジ ベースから応答する、**グラウンディングされた**エージェントを測定します。 これを取得する方法は 2 つあります。

- **[ラボ B](B-integrate-agents-with-enterprise-knowledge-and-m365.md) を行った場合**: `.env` の `AGENT_NAME` をそのエージェントの名前に設定 (既定のままにする場合は `caldova-knowledge-agent`) すれば完了です。
- **行っていない場合**: ここで同等のエージェントを作成します。 サインインして、仮想環境が有効な `Python` フォルダーから次を実行します。

    ```
    az login
    ```

    ```
    python ../setup/bootstrap_agent.py
    ```

    これにより、`Python/knowledge/` のドキュメントがアップロードされ、ファイル検索を使用して `caldova-knowledge-agent` という名前のエージェントがそのドキュメントでグラウンディングされ、`AGENT_NAME` があなたの `.env` に書き込まれます。

> タスク 1 ではこのエージェントが必要ありません — 自動的に作成され、削除されます。

## タスクの準備ができているかを確認する

各タスクには `.env` に固有の値が必要です。 タスクを始める前に、VS Code で開いた `Python` フォルダーからプレフライト チェックを実行してください。`.env` を読み取り、足りないものがある場合は教えてくれます。

```
python ../setup/check_env.py --task 1
```

`1` をこれから始めるタスク番号に入れ替えます。

> **ヒント**: プレフライト チェックは Python 標準ライブラリのみを使用するため、`pip install` の前や仮想環境がアクティブでない場合でも安全に実行できます。 Application Insights が接続されているかどうかは確認できません。それはプロジェクト設定であり、`.env` の値ではないので、タスク 1 から始める場合は上記の接続ステップを実行してください。
